# GSB Bugfix Task
## 题面
跨服移民功能上线第一周，运营后台就积了一堆工单：同一个角色连着提交两次转服，两条请求都生效，落地后背包少了一半东西，找客服也查不到去向；目标服名额已经满了，系统还在继续放行，两个角色抢同一个位置；转服请求挂着的时候，角色还能回原服打副本，排行榜积分照刷，还能把身上的东西寄给别人，落地后两边账对不上；确认超时没人处理，玩家第二天上线卡在中间态，原服进不去，目标服也进不去，客服手工补发物品之后，同一件装备在源服和目的小号各出现一份；刚落地就申请下一次转服，冷却时间形同虚设；溢出到邮箱的装备到期后还能取，连点两下还能取第二份；待转入的名额没有计入目标服人数，运营看报表和实际在线对不上。server_migration.py 定义 ServerMigration，对外暴露 state、request、cancel、confirm、expire、mailbox、claim。服务器容量按在场角色加待转入预留一起算；角色携带上限按物品总数量算，超出的部分按物品名字典序整件保留，装不下的整件转成邮件，邮件按落地时刻加配置里的保留时长算出到期时刻；确认后角色落到目标服并获得一段锁定期，锁定期内不能再申请转服；取消和过期都要释放预留名额并清掉挂起状态；转服编号在全服范围内不允许出现相同值，角色或目标服不存在、同服迁移、重复编号、二次申请一律报 ValueError；request 要记录来源服、目标服、创建时间和截止时间，confirm 之前角色仍算在源服在场但状态标成 pending；邮件只能由本人领取，领取后状态改成 claimed，已领取或已过期的邮件都不能再取；过期的挂起单不能再被取消；角色条目带 pending 与 lock_until，邮件带 mail_id、items、expires、status，state 返回 transfers、characters、mailboxes 的深拷贝。

